Home Network

I replaced the ISP router with a firewall I built myself. That meant specifying hardware against real constraints — Intel NICs only, AES-NI required, two or more ports — installing OPNsense on it, and cutting the house over to it without a long outage.

It now runs recursive DNS with DNSSEC and network-wide filtering, with a NAT rule forcing every client to use it so no device can quietly opt out. Two access points, 21 clients, and an isolated virtual network for the lab below.

The repository has the topology diagram, the design decisions with their tradeoffs, and a write-up of an outage I caused during the cutover and then diagnosed — a VPN kill switch that did exactly what it was built to do, at the worst possible moment.

OPNsense · Unbound DNS · DHCP · firewall and NAT rules · hardware selection

Windows Server Active Directory Lab

A working Windows domain built from nothing on KVM: a domain controller providing directory, DNS and DHCP services, and a client machine joined to it across an isolated virtual network I defined in XML because the GUI would not expose the setting I needed.

The part worth reading is the troubleshooting log. Three problems, each written as symptom, hypotheses, evidence, root cause, and fix — including one where my first hypothesis was reasonable and wrong, which I left in rather than tidying away.

Windows Server · Active Directory · DNS · DHCP · KVM/libvirt · PowerShell

Cisco Network Builds

Switching and routing topologies built in Packet Tracer and configured entirely from the command line, working toward the CCNA. The first build segments a switch into three departmental VLANs.

Each build states its connectivity intent before testing, including what should fail. The VLAN build includes a test most writeups skip: two hosts placed in the same subnet but different VLANs, proving the switch enforces separation independently of IP addressing.

Cisco IOS · VLANs · switching · Packet Tracer
